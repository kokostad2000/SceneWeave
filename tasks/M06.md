## 一、需求

**R1 产品流程（PRD 6.1）。** 开启可选分析能力 → 选择一个本场角色 → 选择**已经提交的公开发言及公开事件** → 预览送出材料 → 点击分析 → 在独立抽屉查看结果。默认**不送出任何私有背景或定向事件**，即使操作者可以看到这些信息。

**R2 材料保真（PRD 6.1）。** 输入保留**原文、来源角色与消息 ID**，不额外调用一个模型“猜测该角色做了什么”。超出接口长度上限时提示缩小选择，**不静默截断，也不自动总结**。

**R3 结果内容（PRD 6.1）。** 展示行为标签、可能机制、**至少两种替代解释**、局限及免责声明。不把模型置信度显示成经过校准的事实概率。结果**不进入角色记忆、不改变人设、不触发调度**；分析失败或受限**不能影响聊天**。

**R4 已结束场景仍可分析（PRD 6.1）。** 沿用本场分析预算。

**R5 现有仓库适配（PRD 6.2）。** 复用 `kokostad2000/behavior-psychology-v2.0`（基线 `bd1e8fa…`）：`BehaviorAnalyzer.analyze(AnalysisRequest)` 异步接口 + 结构化响应；`behavior_description` 与 `context` 各 ≤4000 字符；`persist_profile` 默认关闭。通过 `BehaviorAnalysisAdapter` 直接 Python 调用，**不改变外部仓库**；**只在该适配层**导入外部 `src` 包（本项目用 `role_theater` 包名避开其顶层 `src`）。

**R6 可选依赖（PRD 6.2）。** 通过可选依赖锁定提交，并在干净虚拟环境验证安装、知识库打包和导入；**禁用分析时不得要求外部包已安装**。

**R7 受控客户端（PRD 6.2）。** 强制 `persist_profile=false`；对当前分析器注入**受控兼容客户端**，显式设置 API 行为、**关闭隐式重试**并**追踪使用量**；不要仅依靠其 `temperature=0.2` 推断思考模式已关闭。受控客户端的兼容性由联调测试证明，**不能假定所有供应商接口完全相同**。

**R8 状态区分（PRD 6.2）。** `normal`／`blocked`／`degraded`／`failed`／`disabled` 五种结果状态必须区分；保留 `degradation_flags`，不把返回 JSON 当成分析成功；**库内部吞掉供应商异常并返回降级结果时也必须被识别**。

**R9 预算与计数（PRD 5.3）。** 分析请求上限默认 4，与角色请求**独立计数**；每次实际发送占用一次，失败／超时不退款；被**本地边界规则**拦截时记录一次分析操作，但 `provider_attempts=0`；**用户可见的分析操作数与实际模型请求数分开**。

**R10 隔离与记录（PRD 6.2）。** 分析记录由本项目按 `scene_id`／`agent_id` 隔离；不写入外部画像（`persist_profile` 强制关闭）。

## 三、规范

### 3.1 模块与职责

```

  boundary.py            # 纯函数：材料选择校验 + behavior_description／context 构建
  controlled_client.py   # 受控兼容客户端：显式行为、无隐式重试、用量追踪

```

### 3.2 边界规则（纯函数）

允许送出的材料**只有**：

| 类型 | 条件 |
|---|---|
| 角色公开发言 | 已提交（`messages`） |
| 公开事件 | 状态为 `EFFECTIVE` **且** `visibility=ALL` |

**一律拒绝**：`ACCEPTED`（尚未生效）事件、`TARGETED` 定向事件、任何私有背景／人物设定／初始目标、不存在的序号。

拆分规则：`behavior_description` = 所选角色**本人的公开发言**原文（带 `#seq` 与消息 ID）；`context` = 其他角色的公开发言与公开事件原文（带 `#seq` 与来源）。两者各自 **>4000 字符即拦截**，提示缩小选择，**不截断、不总结**。

### 3.3 五状态与预算

| 情形 | 状态 | `provider_attempts` | 占用分析预算 |
|---|---|---|---|
| 正常返回且无降级标记 | `NORMAL` | ≥1 | 是 |
| 正常返回但带降级标记／结果缺项／库内吞异常 | `DEGRADED` | ≥1 | 是 |
| 本地边界规则拦截（含超长、越界序号、定向事件、预算耗尽） | `BLOCKED` | **0** | **否** |
| 已调用但失败（异常、超时、结构不合法） | `FAILED` | ≥1 | 是 |
| 分析能力关闭，或已开启但外部包不可用 | `DISABLED` | **0** | 否 |

`scene_budget_usage.analysis_requests_used` 只统计**实际发送**；`analysis_records` 的条数即“用户可见的分析操作数”，两者分开呈现。

**降级识别**（PRD 6.2「库内部吞掉供应商异常」）：出现以下任一即判 `DEGRADED`，绝不判 `NORMAL`——
外部结果带非空降级标记、缺少行为标签、缺少替代解释、或结果本身声称降级。

### 3.4 外部适配层

- `ExternalAnalysisPort` 是**唯一**导入外部 `src` 包的位置；
- 模块路径、类名与字段名集中定义在文件顶部常量，**待真实联调核对**（登记为未验证项）；
- 外部包不可导入时：返回 `DISABLED` + 明确原因（含原始 `ImportError` 文本），**不抛异常、不影响聊天**；
- 请求强制 `persist_profile=False`；响应用 `getattr` 容错读取，缺字段一律降级而不是猜。

### 3.5 验收条件

| 编号 | 条件 | 判定方式 |
|---|---|---|
| A1 | 只有公开发言与 `ALL`+`EFFECTIVE` 事件可送出 | 边界纯函数测试 |
| A2 | 私有背景／定向事件／未生效事件一律拦截 | 参数化拦截测试 |
| A3 | 超长各自 >4000 拦截且不截断 | 构造 4000/4001 边界 |
| A4 | 五状态可区分 | 服务层参数化测试 |
| A5 | 降级识别：库内吞异常也判 `DEGRADED` | 假分析器返回缺项／带标记 |
| A6 | `persist_profile` 强制 false | 假分析器断言收到的请求 |
| A7 | 关闭模块可正常聊天 | 关闭状态下跑聊天流程 + 全量回归 |
| A8 | 外部包缺失时明确报告而不是崩溃 | 未安装状态下的能力解析测试 |
| A9 | 预算独立计数；拦截不占预算、失败不退款 | 预算测试 |
| A10 | 无画像写入：只写本项目 `analysis_records` | 表结构 + 记录隔离测试 |
| A11 | 受控客户端关闭隐式重试并追踪用量 | 客户端测试（失败两次只尝试一次、用量记录） |
| A12 | 分析结果不进入角色上下文、不改变运行状态 | 对比分析前后 `viewpoint` 与场景状态 |
| A13 | 前端抽屉接线后可展示结果，降级与局限可见 | 组件测试 |
| A14 | 无越界：不改外部仓库、不改 M00–M05 行为 | 扫描 + 全量回归 |

### 3.6 需求解释与实现选择

- **I1（`behavior_description`／`context` 的拆分）**：PRD 只给出两个 4000 字符字段与“保留原文、来源角色与消息 ID”。M06 取「本人发言 → behavior_description，他人发言与公开事件 → context」，语义最贴近“描述该角色的行为 + 上下文”。
- **I2（拦截也记录）**：PRD 5.3 明确「分析被本地边界规则拦截时记录一次分析操作，但 provider_attempts=0」，因此 `BLOCKED` 也落一条记录。
- **I3（预算耗尽归类）**：归入 `BLOCKED`（本地规则），不占预算、`provider_attempts=0`，并以 `degradation_flags=["analysis_budget_exhausted"]` 说明。
- **I4（外部包路径）**：集中常量 + 容错读取；未安装时 `DISABLED` 并附原因。真实模块路径与字段名属**未验证项**，不得据项目名或历史对话臆造后声称为已验证。
- **I5（不改 M05 骨架）**：前端只在抽屉里注入 `analyze` 回调并渲染结果；未接线时的说明保留给“能力关闭”情形。
