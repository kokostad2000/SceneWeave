# 首版交付收尾与使用观察

## 需求

落实本轮人工指定的三项工作：统一验收资料；冻结 `v0.1.0` 的代码、依赖、迁移与限制；用不同场景持续观察并按影响排序反馈。需求边界仍以 PRD 为准。测试已完成的假设不能替代当前证据，不关闭尚无人工结论的质量验收。

## 目标

1. README、STATUS、ACCEPTANCE、RELEASE 的当前口径一致，历史报告保留原始结果。
2. 建立源码归档、逐文件校验清单和恢复说明；记录 Git HEAD 与工作树差异，不提交、打 Git 标签或推送。
3. 三个预置场景各观察两个独立会话，每场开场最多 6 次行动、公开事件后最多 4 次、定向事件后最多 4 次，并显式选择一次分析；按实际停机条件收尾，不强迫发言。
4. 留存真实原文、SPEAK/PASS、具体回复、模型与请求标识、耗时和 token；输出有证据定位的反馈优先级。

## 规范

- 归属 M07 交付维护；只新增交付／观察脚本、对应测试和文档，不扩展产品功能或改动上游。
- 新观察脚本必须显式 `--live`，使用现有应用配置和真实端口；单次 token 上界沿用应用发送前检查；默认测试使用 Mock。
- 独立数据库、串行会话；上限 84 次角色请求和 6 次分析请求。自然停止或失败减少实际次数，不重试供应商请求。
- 代理阅读样本产生“代理观察”，不得填写或冒充人工验收结论。短时重复会话不证明长期稳定性。
- 基线归档排除凭证、运行数据库、备份、缓存及日志；恢复在项目内独立目录实际执行，逐文件校验并从零重建契约／前端产物。
- 执行命令、退出码、真实结果、未验证项写入 `state/reports/FIRST-RELEASE-2026-09-28.md`。
- 恢复目录末级名保留为 `SceneWeave`，与既有配置路径测试约定一致；首次以版本号作末级名的失败保留，不修改断言。
