## 一、需求

**R1 角色模板。** 模板保存名称、人物设定、表达习惯、初始目标、私有背景五项内容，支持创建、编辑、复制、列表查看与移除（PRD 3.2）。字段长度按 Unicode 码点校验：名称 ≤30／人物设定 ≤1000／表达习惯 ≤300／初始目标 ≤500／私有背景 ≤1000，空白裁剪后校验（PRD 3.3）。

**R2 本场角色实例。** 创建本场角色时保存**模板快照**、**模板来源 ID** 和**新的 `agent_id`**；模板后续改动**不得**影响历史与已有会话（PRD 3.2）。

**R3 角色集合与规模。** 默认三人，可在 2～8 人之间配置；界面、调度、模型调用和测试均按**集合**处理，数据库**不得**使用 `agent1`／`agent2`／`agent3` 等固定列（PRD 1.2、3.2）。

**R4 名称唯一。** 名称是显示字段，`agent_id` 是关联主键；同一场景内名称不可重复，复制后必须改成不重复名称（PRD 3.2）。

**R5 预置场景。** 预置“三个室友的客厅”：安然（主动热情，想找人一起度过晚上，私有背景是朋友临时取消聚会）、许川（表达直接，想休息，私有背景是今天工作很累）、陈禾（刚搬来，想融入但不想打扰）；默认不预设争吵、和解或最终决定（PRD 3.1）。

**R6 预算初值。** 场景创建时可在服务端允许范围内设置每场角色请求上限（**默认 200**；人工裁决 2026-09-26 由 PRD 初值 24 上调，见 `state/STATUS.md` §4 与 `state/reports/CHANGE-role-request-limit.md`）与分析请求上限（默认 4）；**开始后锁定**（PRD 5.3）。

**R7 初始存储。** 建立 SQLite 初始存储与**数据库迁移**机制（PRD 第 8 节“数据库迁移、事件 `schema_version`、模板快照……现在就做”）。

**R8 API。** 提供角色模板与本场角色的 HTTP 接口；请求／响应结构进入契约层并登记到 `registry.py`，随后重新生成前端类型（PRD 第 8 节）。

**R9 锁定语义。** 首次实际角色请求开始后锁定本场背景与人物设定；锁定后不能删角色、不能改写私有背景（PRD 3.2）。M01 提供 `locked_at` 语义与拒绝写入的判定；在“首次角色请求时调用锁定”由 M04 触发。

**R10 范围限制。** 不实现 ContextBuilder／Scheduler（M02）、真实模型适配（M03）、状态机／事件／SSE／预算扣减（M04）、正式业务界面（M05）、行为分析（M06）。

**R11 核验。** 按 `AGENTS.md` 第 5.1 节由开发代理核验：重建检查、反例检查、越界检查、环境矩阵检查；无密钥、无外网。

## 二、目标

1. 后端具备“模板 → 本场快照 → 角色集合”的完整数据链路，并有 SQLite 持久化与版本化迁移。
2. 提供可用的模板与场景 HTTP API，错误语义明确（404 未找到／409 冲突或已锁定／422 校验失败）。
3. 满足 PRD 第 9 节 M01 通过条件：**三人增至五人不改代码**；**旧场景不受模板改动影响**。
4. 预置场景可由一次 API 调用创建，包含三名预置角色。
5. 契约类型重新生成，前后端测试全绿；本模块的临时数据库不进仓库。

## 三、规范

### 3.1 目录与职责

```
backend/role_theater/
  storage/
    database.py            # 短连接 + 显式事务
    migrator.py            # 迁移发现、校验、应用（含 checksum 漂移检测）
    migrations/001_initial.sql
    templates_repo.py      # 模板数据访问
    scenes_repo.py         # 场景／本场角色数据访问
  domain/
    errors.py              # NotFound / Conflict / Locked / Invalid
    templates.py           # TemplateService
    scenes.py              # SceneService
  presets.py               # 预置“三个室友的客厅”
  contracts/api.py         # M01 请求／响应模型（登记进 registry.py）
  api/templates.py         # /api/templates
  api/scenes.py            # /api/scenes
```

### 3.2 数据模型（SQLite）

- `agent_templates(template_id PK, name, persona, speech_style, initial_goal, private_background, is_preset, created_at, updated_at)`
- `scenes(scene_id PK, title, background, status, pause_reason, schema_version, max_role_requests, max_analysis_requests, budget_locked_at, preset_key, created_at, started_at, ended_at)`
- `scene_agents(agent_id PK, scene_id FK, name, order_index, source_template_id, snapshot_name, snapshot_persona, snapshot_speech_style, snapshot_initial_goal, snapshot_private_background, snapshot_captured_at, created_at)`，并含 `UNIQUE(scene_id, name)` 与 `UNIQUE(scene_id, order_index)`
- `schema_migrations(version PK, name, checksum, applied_at)`

硬性约束：**不得**出现 `agent1`／`agent2`／`agent3` 之类列；`scene_agents.source_template_id` **不设外键**，因为模板删除后快照必须继续可用。

### 3.3 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/templates` | 创建模板 |
| `GET` | `/api/templates` | 模板列表 |
| `GET` | `/api/templates/{template_id}` | 模板详情 |
| `PATCH` | `/api/templates/{template_id}` | 编辑模板（部分字段） |
| `POST` | `/api/templates/{template_id}/copy` | 复制模板（须得到不重复名称） |
| `DELETE` | `/api/templates/{template_id}` | 移除模板 |
| `POST` | `/api/scenes` | 创建场景（含 2～8 名本场角色） |
| `POST` | `/api/scenes/preset` | 用预置“三个室友的客厅”创建场景 |
| `GET` | `/api/scenes` | 场景列表（含角色数） |
| `GET` | `/api/scenes/{scene_id}` | 场景详情（含角色集合与快照） |
| `POST` | `/api/scenes/{scene_id}/agents` | 由模板新增本场角色 |
| `PATCH` | `/api/scenes/{scene_id}/agents/{agent_id}` | 重命名本场角色 |
| `DELETE` | `/api/scenes/{scene_id}/agents/{agent_id}` | 移除本场角色 |

错误映射：`NotFoundError`→404；`ConflictError`（重名、数量越界、未知模板）与 `SceneLockedError`→409；契约校验失败→422。错误体沿用 M00 的 `ApiError`。

### 3.4 业务规则

- 创建场景时校验 2～8 名角色；新增后不得超过 8；移除后不得少于 2。
- 同场景内角色名唯一（大小写敏感，裁剪空白后比较）；模板名同样唯一（见 §3.6 I1）。
- 锁定（`budget_locked_at` 非空）后：新增／重命名／移除角色一律 409，且不得改写快照。
- 复制模板：未给出名称时自动取第一个可用名 `原名（副本N）`；显式给出已被占用的名称时 409。
- 移除模板**不**影响任何已创建场景（快照隔离）。
- 预置场景创建时会**按需补齐**被删除的预置模板，保证预置流程可重复使用。

| 编号 | 条件 | 判定方式 |
|---|---|---|
| A1 | 模板 CRUD 与五项长度校验按码点执行 | API 测试 + 边界用例 |
| A2 | **三人增至五人不改代码** | 参数化测试覆盖 2／3／5／8 人，全部由数据驱动 |
| A3 | **旧场景不受模板改动影响** | 改模板后重读场景详情，快照字段不变 |
| A4 | 名称唯一与复制改名 | 同场景重名 409；复制自动改名／显式重名 409 |
| A5 | 快照含 `source_template_id` 与新 `agent_id` | 场景详情断言 |
| A6 | 迁移可用且幂等；无 `agent1/2/3` 列 | 迁移测试 + 直接读取 `sqlite_master` |
| A7 | 数量边界：<2 或 >8 被拒绝 | 创建 1／9 人 422；移除到 1 人 409；新增到 9 人 409 |

| A9 | 预算上限创建时可设、开始后锁定 | 创建时设置生效；锁定后接口拒绝改预算（M01 无改预算接口，以锁定标记断言） |

### 3.6 需求解释与实现选择（记录理由）

- **I1（模板名唯一）**：PRD 只明确“同一场景内名称不可重复，复制后必须改成不重复名称”。M01 将“名称唯一”统一施加于模板与场景内角色两类资源。理由：模板复制是 PRD 明确的流程，若模板可重名则“复制后必须改成不重复名称”无从判定；统一规则最简单且不减少任何功能（用户可随时改名）。**不影响产品边界**。
- **I2（场景背景编辑接口）**：PRD 流程为“打开预置场景 → 添加或修改角色 → 创建本场会话”，背景在创建时确定。M01 **不提供**背景编辑接口，因此不存在“悄悄改写背景”的路径；人物设定同理只能通过创建时的快照写入。锁定语义由 `budget_locked_at` 承载。
- **I3（存储实现）**：使用标准库 `sqlite3` + 显式 SQL 迁移，不引入 ORM。理由：单进程单 worker（PRD 1.3），需要精确控制事务边界（PRD 5.4 要求模型等待期间不得持有写事务），且避免为简单 CRUD 增加依赖。
- **I4（并发写入）**：M01 面向单用户本地部署（PRD 1.3），采用“先检查后写入”，并由数据库 `UNIQUE(scene_id, name)` 作为最终防线；不引入显式锁或 `SELECT FOR UPDATE`。
- **I5（陈禾私有背景）**：PRD 3.1 未给出陈禾的私有背景。M01 **留空**并注明原因，**不编造**具体私有事实（`AGENTS.md` 第 5.1 节）。
- **I6（预置角色文案）**：人物设定／表达习惯／初始目标取自 PRD 3.1 的原文措辞（如“主动热情”“想休息”“刚搬来”），仅做字段映射，不添加 PRD 之外的事实。
- **I7（界面）**：配置页等界面属于 M05；M01 只重新生成契约类型。
