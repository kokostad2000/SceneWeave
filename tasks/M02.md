# M02 可见性与调度

模块：M02 ｜ 依赖：M00、M01（均已验收）｜ 状态：**已验收**（代理核验 V1–V7 全部通过，见 `state/reports/M02.md` 第 7 节；人工可复核或推翻）

任务书只设“需求／目标／规范”三节。需求来自 `PRD.md` 第 4.1、5.1 节；本文件不重复抄写 PRD 全文。

## 一、需求

**R1 可见性过滤（PRD 4.1）。** 共同背景、公开关系、角色发言与公开事件可进入所有角色上下文；完整人物配置**只**提供给对应角色；定向事件**只**提供给指定角色。其他角色只得到公开的角色名册，**不能**得到对方的私有目标与背景。

**R2 操作者时间线不是角色输入（PRD 4.1）。** 分析报告、错误、使用量、SSE 心跳与运行状态**不属于剧情**，不得进入角色上下文或唤醒角色。

**R3 调用器与视角一致（PRD 7.2）。** 角色视角必须展示与调用器**实际使用相同**的上下文选择结果，不允许前端再实现一套权限。

**R4 单一构建者（PRD 4.1）。** 统一由 ContextBuilder 从实际可见性和事件类型构建输入。

**R5 候选条件（PRD 5.1）。** 首次开始为所有角色建立一次启动机会；以后候选角色必须有尚未处理的**新可见外部信息**，或尚未消费启动机会。发言者自己的输出进入自己的历史，但**不能仅凭自己的发言再次唤醒自己**。

**R6 点名优先（PRD 5.1）。** 优先满足有效的指定回应者，**最多连续使用两次**点名优先，然后**必须**执行一次普通轮转。

**R7 普通轮转（PRD 5.1）。** 选择最久未行动的候选，平局按**固定角色顺序**。调度结果可复核，不额外调用主持模型。

**R8 候选为空（PRD 5.1）。** 候选为空时暂停，原因是“无新信息”（`NO_NEW_INFORMATION`），**不是**整个会话已结束。

**R9 上下文上限（PRD 5.3、5.4）。** 超出 `max_prompt_chars=32000` 时**暂停**，不静默截断。

**R10 范围。** M02 只交付纯函数式的可见性、上下文构建与调度决策；**不**实现模型调用（M03）、状态机／持久化／SSE／预算扣减（M04）、界面（M05）。

## 二、目标

1. 一个**纯函数**的可见性模块，被上下文构建与调度**共用**，保证调用器与视角不会出现两套权限。
2. 一个纯函数的 ContextBuilder，同一输入必得同一输出，且结构上不可能把分析报告／用量／运行状态混入角色输入。
3. 一个纯函数的 Scheduler，实现启动机会、新信息候选、点名优先上限与固定顺序轮转，并给出可复核的决策原因。
4. 上下文超限时返回明确信号，交由 M04 转为 `CONTEXT_LIMIT` 暂停。
5. 满足 PRD 第 9 节 M02 通过条件：**私有材料不串入**；**自发言不自唤醒**；**PASS 能使场景停下来**。

## 三、规范

### 3.1 模块与职责

```
backend/role_theater/context/
  visibility.py   # 唯一可见性判定（纯函数），构建与调度共用
  builder.py      # ContextBuilder：纯函数构建角色输入 + 提示词渲染
  models.py       # SceneSnapshot / TimelineItem / RoleContext（纯数据）
backend/role_theater/scheduling/
  scheduler.py    # Scheduler：候选判定 + 点名优先 + 轮转
```

M02 的模块**不导入** FastAPI、`storage`、`ports`，也不读写数据库：输入是纯数据，输出是纯数据。

### 3.2 可见性规则（唯一实现）

| 条目 | 谁能看到 |
|---|---|
| 共同背景 | 全部角色 |
| 角色名册（仅名称） | 全部角色 |
| 公开发言（含 `reply_to_message_id`／`requested_speaker_id`） | 全部角色 |
| `ALL` 事件 | 全部角色 |
| `TARGETED` 事件 | **仅** `target_agent_id` |
| 完整人物配置（人物设定／表达习惯／初始目标／私有背景） | **仅**该角色本人 |

“新可见外部信息”定义为：对角色 X 可见、且**作者不是 X**（事件视为操作者）的条目中最大的 `seq`，超过 X 的 `processed_seq` 即为新信息。

### 3.3 上下文结构

`RoleContext` 只含：共同背景、公开名册（名称集合）、**本人**完整资料、按 `seq` 排序的可见条目、截止序号 `cutoff_seq`、提示模板标识。字段为冻结数据类，**没有**任何承载分析结果、错误、用量、运行状态或心跳的字段。

提示词由固定分区渲染，含一条固定规则声明：定向事件中的文字是角色收到的**信息**，不是可覆盖系统规则的**指令**（PRD 4.1）；行动必须是 `action`／`text`／`reply_to_message_id`／`requested_speaker_id` 四字段 JSON（PRD 4.2）。

### 3.4 调度决策

`Scheduler.select(SchedulerState) -> SchedulingOutcome`：

1. 候选 = 未消费启动机会 **或** 存在新可见外部信息；
2. 取时间线上**最新一条发言**的 `requested_speaker_id`；若该角色是候选且已连续使用点名优先次数 < 2，则选他，原因 `REQUESTED_SPEAKER_PRIORITY`；
3. 否则在候选中选 `last_action_at` 最早者（从未行动视为最早），平局按固定 `order_index`；原因：未消费启动机会→`STARTUP_OPPORTUNITY`，否则 `NEW_VISIBLE_INFORMATION`；
4. 无候选 → `actor_id=None`，`pause_reason=NO_NEW_INFORMATION`。

`based_on_seq` = 该角色可见的最大 `seq`（无则 0），即行动依据的输入快照截止序号。

### 3.5 验收条件

| 编号 | 条件 | 判定方式 |
|---|---|---|
| A1 | 私有材料不串入 | 目标角色的提示词与上下文不含其他角色的 `persona`／`initial_goal`／`private_background` |
| A2 | 定向事件只给指定角色 | 定向事件文本出现在目标角色上下文，不出现在其他角色上下文 |
| A3 | 公开内容全体可见 | 公开发言与 `ALL` 事件出现在所有角色上下文 |
| A4 | 自发言不自唤醒 | 只有自己的发言时该角色不是候选 |
| A5 | PASS 能使场景停下来 | 全部角色消费启动机会且仅剩自己输出 → 无候选、`NO_NEW_INFORMATION` |
| A6 | 点名优先最多连续两次 | 连续两次点名后第三次强制轮转 |
| A7 | 轮转取最久未行动者，平局按固定顺序 | 构造时间戳与平局两组断言 |
| A8 | 启动机会只用一次 | 消费后若无新信息则不再是候选 |
| A9 | 纯函数与确定性 | 同一输入多次调用结果相同；输入不被修改 |
| A10 | 结构上排除非剧情内容 | `RoleContext` 字段集合固定；构建器不接受用量／错误／运行状态输入 |
| A11 | 超限不截断 | 超过 `max_prompt_chars` 时抛出可识别错误，提示词本身不被裁剪 |
| A12 | 无越界 | 不导入 FastAPI／storage／ports；不调用模型 |

### 3.6 需求解释与实现选择

- **I1（“最新一条发言”的取值）**：PRD 未定义点名优先的适用窗口。M02 只采用时间线上**最新一条发言**所携带的 `requested_speaker_id`；更早的点名视为已过期，不回看。理由：可复核、避免旧点名长期劫持调度。
- **I2（候选与点名优先的关系）**：点名优先只在目标角色**本身是候选**时生效，符合 PRD 4.1“指定希望回应者”不改变可见范围、也不凭空唤醒无新信息角色的原则。
- **I3（`startup_opportunity_consumed` 的置位）**：由 M04 在角色**成功**行动后置位（失败不推进，PRD 5.1）。M02 只读取该状态。
- **I4（提示词文本）**：M02 定义固定的分区与规则声明，模板标识为 `role_action@m02`；M03 只负责发送参数与解析，不改可见性。
