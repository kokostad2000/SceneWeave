## 一、需求

**R1 工程初始化。** 按 PRD 第 8 节选型建立 React＋TypeScript＋Vite 前端与 FastAPI 后端；后端 Python 包名为 `role_theater`，产品显示名称为 SceneWeave。Python 首版验证环境为 3.12；Node 与依赖的精确版本以 M00 实际兼容安装结果锁定（写入锁文件与报告）。

**R2 最小健康检查。** 提供不需要任何模型密钥即可启动并返回成功的健康检查接口。

**R3 公共请求／响应契约。** 建立公共契约层，作为接口唯一来源：后端请求／响应模型定义全部枚举、字段与长度上限；导出 OpenAPI 并生成前端类型，前后端**不得**各自维护不一致枚举（PRD 第 8 节）。

**R4 行动与事件结构。** 定义 `ActionDraft`（模型只能返回 `action`／`text`／`reply_to_message_id`／`requested_speaker_id` 四个字段）、`ActionType`（`SPEAK`／`PASS` 及其字段约束）、`ActionRecord`、`Message`、`Event`（稳定 `event_id`、单调 `seq`、可见范围、`ACCEPTED`／`EFFECTIVE` 状态、`schema_version`）。规则见 PRD 第 4 节。

**R5 外部接口边界。** 只定义两个外部端口的协议边界：模型行动（`ModelPort`）与行为分析（`AnalysisPort`），以及它们的请求／响应结构与失败分类。**不建通用插件系统**，不在 M00 实现真实模型或真实分析调用。

**R6 测试基线。** 建立不需要真实模型密钥的基础测试，覆盖健康检查、契约字段与枚举一致性、行动协议的合法与失败路径、事件可见性与状态、端口 Mock 行为。

**R7 支撑文件。** 建立 `AGENTS.md`、`docs/ARCHITECTURE.md`、`tasks/M00.md`、`state/STATUS.md`，并在完成后写入 `state/reports/M00.md`。

**R8 范围限制。** 本轮只做工程基础与契约。**不实现**角色管理、聊天调度、场景运行、行为分析或正式业务页面；**不提前实施** M01～M07 的功能；不进行真实模型 API 联调；不索取或写入任何密钥。

**R9 证据要求。** 实际执行必要的检查与测试，记录命令、退出码与结果；环境导致无法运行的项目标记为“未验证”，不得通过删除测试、降低断言或编造结果宣称通过。

**R10 操作范围。** 只在项目目录与项目专用依赖环境内编辑、安装、执行。不修改其它项目、系统服务、防火墙或公网部署配置；不修改心理分析上游仓库；不自动创建远程仓库，不 `git commit`、不 `git push`。

## 二、目标

1. 仓库从“只有 PRD”变为可安装、可启动、可测试的最小工程，目录职责与 `docs/ARCHITECTURE.md` 一致。
2. `GET /api/health` 在**无密钥**环境下返回 200 与稳定的健康负载。
3. 契约层可由后端单一来源导出 OpenAPI，并生成前端 TypeScript 类型；生成结果可复现。
4. 契约测试与基础测试全部在无密钥环境下通过。
5. `state/STATUS.md` 列出 M00～M07 的开发顺序、依赖与当前状态；M00 完成后标记为“待验收”。
6. `state/reports/M00.md` 记录修改文件、实际命令、退出码、测试结果、未验证项与进入 M01 的条件。

**明确不做（属于后续模块）**：角色模板与本场快照、ContextBuilder 与可见性过滤、Scheduler、真实模型客户端与 JSON 校验、状态机与命令幂等、预算扣减与持久化、SSE、任何业务页面与行为分析接线。

## 三、规范

### 3.1 目录与命名

```
backend/pyproject.toml            # uv 管理，包名 role_theater
backend/role_theater/
  contracts/                      # 唯一契约来源（Pydantic v2）
  ports/                          # ModelPort / AnalysisPort 协议 + Mock
  api/                            # 健康检查与契约自检路由
  config.py                       # 运行配置与预算常量
backend/tests/                    # pytest
frontend/                         # React + TS + Vite（pnpm）
  src/api/generated/              # 由 OpenAPI 生成的类型（不手写）
```

- 产品显示名称：`SceneWeave`。Python 导入包名：`role_theater`（**不得**使用 `src`、`agent1`／`agent2`／`agent3` 之类固定列命名）。

### 3.2 健康检查

- `GET /api/health` → 200，字段：`status`（`ok`）、`app_name`（`SceneWeave`）、`app_version`、`contract_version`、`run_state`（`READY`）、`analysis_enabled`（bool）、`model_configured`（bool）。
- 未配置任何密钥时 `model_configured=false`，接口仍返回 200。健康检查**不得**发起任何外部调用。

### 3.3 契约规则

- 枚举：`ActionType`、`EventVisibility`、`EventStatus`、`RunState`、`PauseReason`、`AnalysisStatus`、`ModelFailureKind`。
- 长度上限（Unicode **码点**，裁剪空白后校验）：名称 30／人物设定 1000／表达习惯 300／初始目标 500／私有背景 1000／场景背景 2000／事件正文 1000／`SPEAK.text` 200（下限 1）／`behavior_description` 4000／`context` 4000。
- `ActionDraft` 严格四字段；出现额外字段即失败（`schema_invalid`）。
- `PASS`：`text` 与两个引用字段均为空，否则失败。`SPEAK`：`text` 1～200 码点。
- `ModelActionResponse` 区分成功与 `ModelFailure`；失败类型至少覆盖 `EMPTY_CONTENT`、`TRUNCATED`、`INVALID_JSON`、`SCHEMA_INVALID`、`REFERENCE_INVALID`、`TIMEOUT`、`PROVIDER_ERROR`、`CONTEXT_LIMIT`。**契约层不做静默修剪、不自动广播、不追加修复调用**（真正的判定在 M03／M04 实现）。
- `Event`：`seq` 单调、`event_id` 稳定；`ACCEPTED` 与 `EFFECTIVE` 区分；`TARGETED` 必须带 `target_agent_id`，`ALL` 不得带。
- `Budget` 常量：`max_role_requests=24`、`max_analysis_requests=4`，独立计数。（**2026-09-26 人工裁决**：角色请求默认值上调为 200，分析仍为 4；M00 交付时的 24 是 PRD 初值，PRD 原文未改。）
- 运行参数常量：`model=deepseek-flash`、`max_output_tokens=1024`、`request_timeout_seconds=90`、`sdk_max_retries=0`、`max_prompt_chars=32000`、`thinking_enabled=False`、`stream=False`、`response_format=json_object`、`tools` 不发送。
- 分析：`persist_profile` **强制 false**（传入 true 必须被拒绝或强制覆盖，M00 采用拒绝并报错）。`AnalysisPort` 默认实现在禁用分析时**不导入**任何外部包。

### 3.4 测试规范

- `pytest` 必须在无密钥环境下通过；默认路径使用 Mock／Fake，不产生网络调用（测试中禁止真实外部请求）。
- 至少覆盖：健康检查 200 且无密钥依赖；OpenAPI 可导出且包含 M00 路由；枚举取值集合固定；`ActionDraft` 额外字段被拒绝；`PASS` 携带文本被拒绝；`SPEAK` 空文本与超 200 码点被拒绝；码点计数在多字节字符与 emoji 上正确；`Event` 定向／全体可见性校验；`AnalysisRequest` 拒绝 `persist_profile=true` 与超长输入；Mock 端口返回确定结果。
- 前端 `vitest` 至少覆盖：类型生成产物存在且枚举一致、基础渲染/健康状态展示不依赖后端密钥。
