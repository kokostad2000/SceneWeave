## 一、需求

**R1 硬验收逐条对照（PRD 10）。** 建立 `docs/ACCEPTANCE.md`，把第 10 节列出的硬验收项（2／3／5／8 人配置、快照隔离、可见性过滤、SPEAK／PASS 协议、公平调度、暂停／结束、事件顺序、预算、空响应与截断、重入幂等、SSE 追赶、重启暂停、分析隔离、依赖可选性）逐条对应到**实际测试**与命令。

**R2 Mock 与真实证据分开（PRD 10、第 9 节 M07）。** 所有确定性验收用可控 Mock 完成；真实模型验收必须使用**显式 live 开关与有效配置**，**不在普通 CI 自动花费**。**缺少授权或密钥时记录为未验证，绝不替换成 Mock 后标记通过**。

**R3 发布资料（PRD 10）。** 至少包括：启动说明、配置项、依赖锁、数据库迁移方法、备份恢复方法、已知限制、模块证据与真实调用样例。

**R4 安装与启动可复现（PRD 第 9 节 M07）。** 从干净环境按 README 的步骤可安装、启动、测试。

**R5 恢复与演示证据（PRD 第 9 节 M07、5.4）。** 提供并实际执行：崩溃恢复（不重放付费请求）、备份与恢复、假模型端到端演示。

**R6 交付结论（PRD 10）。** 只在证据完整时给出“可试用”；服务未真正部署或真实模型未接通时**必须明确列出缺项**。

**R7 范围。** M07 原则上不新增功能代码，只做回归、脚本、文档与证据整理。

## 二、目标

1. `docs/ACCEPTANCE.md`：硬验收 → 测试 → 命令的证据矩阵。
2. `docs/RELEASE.md`：启动、配置、依赖锁、迁移、备份恢复、已知限制、真实调用样例（标注未验证）。
3. 三个可执行脚本：`live_smoke.py`（显式 live 开关，无密钥时**拒绝运行并说明**）、`quality_observation.py`(聊天质量观察样本)、`backup_db.sh`（SQLite 备份）。
4. 一个假模型端到端回归测试：三人聊天 + 定向事件 + 行为分析 + 时间线/预算/视角/历史只读。
5. 实际执行：全量回归、真实 HTTP 端到端、崩溃恢复、备份恢复、无密钥 live 拒绝。
6. 给出**诚实的交付结论**：可试用与否 + 缺项清单。

## 三、规范

### 3.1 产物

```
docs/ACCEPTANCE.md               # 硬验收证据矩阵（PRD 10）
docs/RELEASE.md                  # 发布资料 + 已知限制 + 真实调用样例（未验证标注）
backend/scripts/live_smoke.py    # 真实模型冒烟（显式 live 开关，无密钥拒绝运行）
backend/scripts/quality_observation.py  # 聊天质量观察样本生成（不替代人工观察）
scripts/backup_db.sh             # SQLite 备份（含 WAL 检查点）
backend/tests/test_m07_end_to_end.py    # 假模型端到端回归
```

### 3.2 live 开关规则

- 只有显式传入 `--live` **且**存在 `SCENEWEAVE_MODEL_API_KEY` 时才发起真实调用；
- 缺任一条件：打印**缺项说明**并以非零退出码结束，**绝不**回退成 Mock 后宣称通过；
- 真实调用的结果写入 `state/reports/live/`（若产生），并在验收矩阵中标记来源；
- 普通 `pytest` 不包含任何真实花费。

### 3.3 备份与恢复

- 备份：先做 WAL 检查点，再复制 SQLite 文件（单文件事实来源）；
- 恢复：把备份文件放回 `SCENEWEAVE_DATABASE_URL` 指向的路径，启动时自动执行迁移（幂等）；
- 二者都必须**实际执行并验证数据完整**，而不是只写文档。

### 3.5 需求矛盾与实现选择

- **I1（PRD 10 的「预置三个场景各运行三次」）——已由人工裁决**：PRD 第 3.1 节只定义了**一个**预置场景，第 10 节要求三个。项目负责人裁决为**补两个预置场景**（不改 PRD 原文），因此新增 `convenience_store` 与 `campsite`，每个 3 名角色；这两个场景的角色与情境是**项目自撰的虚构内容**，不得被表述为 PRD 的规定内容，撰写时遵守 PRD 3.1 的约束（不预设争吵／和解／最终决定）。`quality_observation.py` 现按「三个场景 × 三次」执行。
- **I2（人工观察仍是人工）**：`quality_observation.py` 只生成样本与统计（是否回应具体内容／是否泄露未提供的私有事实等可机器判定的部分），**不替代** PRD 要求的人工观察，报告中标记为未验证。
- **I3（不新增功能代码）**：M07 只增加脚本、测试与文档；若发现缺陷，修在对应模块并同步其报告。
