## 一、需求

**R1 状态机（PRD 5.2）。** 状态固定为 `READY`／`RUNNING`／`PAUSING`／`STOPPING`／`PAUSED`／`ENDED`。单步只执行一次角色请求、不保证产生发言、完成后暂停；自动运行按相同规则继续。暂停／结束在**当前调用边界**生效，当前调用按超时配置有界收尾，**不新建下一次调用**。达到角色调用上限 → `ENDED`；`ENDED` 不可恢复运行。

**R2 原因可区分（PRD 5.2）。** 无新信息、人工暂停、接口错误、上下文上限与进程中断都要进入 `PAUSED`，但**原因必须区分**。

**R3 人工事件（PRD 4.3）。** 事件含正文与可见范围（全体或一个本场角色），不做角色间私聊，也不把操作者变成第四个角色。暂停时提交**立即生效但不自动继续**；调用进行中提交先保存为**待生效**，当前调用结束或失败后按**接受顺序**生效，再决定是否继续调度。界面区分「已接受」与「已生效」。结束请求之后**拒绝**新事件；此前接受的事件在调用边界顺序落盘，但**不再触发新行动**。已生效事件不可编辑或删除。

**R4 幂等（PRD 5.4）。** 控制命令携带 `request_id`；同一命令重复提交返回**既有结果**。场景内事件拥有稳定 `event_id` 与单调 `seq`，行动拥有 `turn_id` 与 `attempt_id`。数据库约束**防止一份成功行动重复成为公开消息**。**先提交记录，再向界面推送**；模型网络等待期间**不得持有 SQLite 写事务**。

**R5 预算（PRD 5.3）。** 每场角色请求上限**默认 200**（人工裁决 2026-09-26 由 PRD 初值 24 上调）、分析请求上限默认 4，独立计数，各自最多一个在途请求。**每次实际发送都占用一次**，失败、超时与人工重试**不退款**。发送结果不明时保守占用并标记 `UNKNOWN`，不得假装未发送而自动重发。入站参数校验失败、缺少配置而尚未发送 → **不新增模型请求**。控制方式不变：单步只执行一次调用后停下等人工决定，自动运行按原规则推进。

**R6 刷新、断线与重启（PRD 5.4）。** 页面刷新只恢复视图，不重启任务；浏览器断开不自动停止后台场景，预算继续有效。进程重启后把遗留在途请求标记 `UNKNOWN` 并暂停会话，**不自动恢复付费请求**；恢复边界先处理尚未生效的已接受事件，再允许新的角色请求。

**R7 SSE（PRD 第 8 节）。** SSE 从**已提交事件按 `seq` 补发**，支持断线追赶与事件去重。数据库事件是事实来源，**不把多消费者 Queue 当广播**。

**R8 视角一致（PRD 7.2）。** 角色视角接口必须展示与调用器**实际使用相同**的上下文选择结果。

**R9 历史（PRD 5.4）。** 历史播放只读取已保存数据，不调用模型。

**R10 范围。** 不实现正式界面（M05）与行为分析（M06）。

## 二、目标

1. SQLite 迁移 002：事件、消息、行动、游标、命令幂等与 `seq` 分配。
2. 一个可测试的运行器：状态机 + 单步 + 自动运行 + 暂停／结束 + 预算 + 事件注入排序 + 崩溃恢复。
3. HTTP 接口：控制命令、事件注入、时间线、角色视角、SSE 流。
4. 满足 PRD 第 9 节 M04 通过条件：**假模型端到端**；**暂停排序正确**；**重连与重启不重放请求**。

### 3.2 数据表（迁移 002）

| 表 | 关键约束 |
|---|---|
| `messages` | `UNIQUE(scene_id, seq)`；`seq` 与事件共享场景内单调序列 |
| `events` | `UNIQUE(scene_id, seq)`；`status ∈ {ACCEPTED, EFFECTIVE}`；`EFFECTIVE` 必须有 `effective_at` |
| `scene_turns` | `attempt_id` 唯一；`message_id` 唯一（**防止一份成功行动重复成为公开消息**）；`status ∈ {PENDING, SUCCEEDED, FAILED, UNKNOWN}` |
| `role_cursors` | `PRIMARY KEY(scene_id, agent_id)`；`processed_seq`、`startup_opportunity_consumed`、`last_action_at` |
| `scene_commands` | `request_id` 主键 → 幂等重放返回既有结果 |
| `scene_seq` | 每场 `last_seq` 计数，事务内原子自增 |
| `scene_budget_usage` | `role_requests_used`、`analysis_requests_used` |

**`PENDING` 是关键**：派发前先写 `PENDING` 行（同时占用预算），返回后改为 `SUCCEEDED`／`FAILED`／`UNKNOWN`。进程重启时把残留 `PENDING` 一律标记 `UNKNOWN` 并把所属场景置为 `PAUSED`（原因 `PROCESS_INTERRUPT`）——这就是「不自动恢复付费请求」的实现方式。

### 3.3 单步与自动运行

- `STEP`：在当前调用边界执行**恰好一次**角色请求，然后进入 `PAUSED`（原因 `MANUAL`）。不保证产生发言（可能是 PASS）。
- `START`／`RESUME`：进入 `RUNNING` 并启动后台循环；循环内每次迭代都在调用边界检查停止标志。
- `PAUSE`：置 `PAUSING`；若当前无在途调用则立即 `PAUSED`。`STOP`：置 `STOPPING`；在途调用结束后落盘已接受事件，然后 `ENDED`。
- 循环退出条件：无候选（`NO_NEW_INFORMATION`）、人工暂停／结束、调用失败、上下文超限、预算耗尽（`ENDED`）。

### 3.4 事件排序

1. 场景为 `ENDED` 或已收到结束请求 → **拒绝**新事件（409 `scene_ended`）。
2. 无在途调用（`READY`／`PAUSED`／无循环）→ 写入即 `EFFECTIVE`；**不自动继续**。
3. 有在途调用 → 写 `ACCEPTED`；当前调用落盘后，按 `accepted_at` + 自增顺序把 `ACCEPTED` 依次转为 `EFFECTIVE`。
4. 结束请求之后不再触发新行动，但已接受事件仍在调用边界顺序落盘。

### 3.5 幂等与推送顺序

- 命令：先查 `scene_commands.request_id`；命中则直接返回既有 `response_json`，`deduplicated=True`，**不新增模型请求**。
- 落盘顺序：先写数据库（消息／事件／行动／游标），**再**通过 `Broadcaster` 通知 SSE 订阅者。SSE 只按 `seq` 补发已提交数据，`seq` 去重。
- 模型网络等待期间不持有写事务：`PENDING` 写入与结果写入各自是独立短事务。

### 3.6 验收条件

| 编号 | 条件 | 判定方式 |
|---|---|---|
| A1 | 假模型端到端 | 用 `MockModelPort` 跑完三角色若干轮：消息按 `seq` 落盘，角色集合不变 |
| A2 | 单步只执行一次调用 | 记录端口调用次数 |
| A3 | 暂停排序正确 | 在途调用期间注入两个事件，断言只有调用结束后按接受顺序生效，且 `ACCEPTED`→`EFFECTIVE` 顺序稳定 |
| A4 | 暂停时的事件立即生效但不自动继续 | 状态保持 `PAUSED`，无新增调用 |
| A5 | 结束请求后拒绝新事件；已接受事件仍落盘且不触发新行动 | 断言 409 与事件状态、调用次数不变 |
| A6 | 命令幂等 | 同一 `request_id` 重复提交返回相同结果且调用数不变 |
| A7 | 预算：发送即占用、失败不退款、耗尽即 `ENDED` | 构造失败脚本与超限场景 |
| A8 | 发送结果不明保守占用并标 `UNKNOWN` | 注入 `UNKNOWN_REQUEST` 失败，断言占用与状态 |
| A9 | 未发送不占用预算 | 上下文超限／缺配置路径断言预算不变 |
| A10 | 重连不重放请求 | SSE 追赶只补发已提交条目，重复连接不新增调用 |
| A11 | 重启不自动恢复付费请求 | 制造残留 `PENDING` → 重启 → 标记 `UNKNOWN`、场景 `PAUSED`、调用数 0 |
| A12 | 视角与调用器一致 | 视角接口返回的上下文与运行器构建的一致 |
| A13 | 历史只读不调用模型 | 查询时间线后端口调用数不变 |
| A14 | 无越界 | 不实现界面与分析；`PENDING` 期间的写事务不跨越网络等待 |

### 3.7 需求解释与实现选择

- **I1（自动运行的执行形式）**：单个 uvicorn worker 内、每场景一个 asyncio 后台任务。理由：本地单用户（PRD 1.3），且「生成中按钮仍可接收暂停／结束」（PRD 7.1）要求控制命令与生成并发。命令立即返回，界面靠 SSE 观察。
- **I2（`PENDING` 行的作用）**：同时承担「占用预算」「标记在途」「崩溃恢复依据」三件事，避免多处状态不一致。若客户端返回「未派发」类失败（`CONTEXT_LIMIT`／`MISSING_CONFIG`／`NOT_DISPATCHED`），则回退该次占用，因为它没有产生模型请求（PRD 5.3）。
- **I3（SSE 形式）**：`text/event-stream`，每条 `id: <seq>`、`event: timeline`；心跳为注释行（`:\n\n`），**不进入剧情**，也不产生 `seq`。提供可选 `replay_limit` 以支持有界追赶（客户端可分批拉取）。
- **I4（事件不可编辑／删除）**：不提供任何写入已有事件的接口，只提供追加。
- **I5（预算上限锁定）**：M01 已在场景创建时写入上限并可由 `lock()` 锁定；M04 只做扣减与判定，不修改上限。
