## 一、需求

**R1 运行参数固定（PRD 2.2）。** 默认 Chat Completions 接口、`model=deepseek-flash`、`stream=false`、`response_format=json_object`、**显式关闭思考**、**不发送 tools**；默认最多输出 1024 tokens、请求总期限 90 秒、**SDK 自动重试为零**。不发送 `reasoning_effort=100`，也不能用较低 temperature 假设思考已关闭。

**R2 记录要素（PRD 2.2）。** 记录请求模型名、服务端返回模型名、参数、提示模板标识、请求 ID 与使用时间；别名可能变化，因此两个模型名都要记录，且不宣称同一别名可永久复现同一底层模型。

**R3 严格解析（PRD 4.2）。** 模型只返回 `action`、`text`、`reply_to_message_id`、`requested_speaker_id` 四个字段。服务端还要检查枚举、字段完整性、**额外字段**、文本长度、角色与消息引用。空 content、`finish_reason=length`、格式异常、非法引用与过长正文都视为失败；**不得静默修剪、自动广播或追加修复模型调用**。

**R4 用量（PRD 5.3）。** 用量以服务端返回为准，**缺失记为 unknown 而非零**；按输入、输出、缓存命中（若返回）记录原始用量。本期不承诺货币费用。

**R5 不发送即不消耗（PRD 5.3）。** 入站参数校验失败、缺少配置而尚未发送的调用**不新增模型请求**；发送结果不明时保守占用预算并标记 `UNKNOWN`，不得假装未发送而自动重发。

**R6 端口形态（PRD 第 8 节）。** 实现既有的 `ModelPort` 协议；未配置凭证时**必须**回落到确定性 Mock，绝不发起网络调用。

**R7 范围。** 不实现调度与游标推进（M02 已交付）、状态机／预算扣减／幂等命令／SSE（M04）、界面（M05）。

## 二、目标

1. 一个真实可用的 DeepSeek Chat Completions 客户端，且**在无网络、无密钥环境下可完整测试**（通过 `httpx.MockTransport`）。
2. 解析与引用校验是**纯函数**，可脱离 HTTP 单独测试。
3. 每个失败路径都有独立分类，没有“看起来成功”的路径。
4. 契约层补上两项必要能力：允许的引用范围 `ReferenceScope`，以及“本地拒绝发送但不占用预算”的表达方式。
5. 满足 PRD 第 9 节 M03 通过条件：**关闭隐式重试**；**空输出、截断等按契约失败**。

## 三、规范

### 3.1 模块与职责

```
backend/role_theater/ports/
  deepseek.py       # DeepSeekModelClient：请求构造、发送、响应解析、用量
  action_parser.py  # parse_action_content / validate_references（纯函数）
  model.py          # ModelPort 协议、MockModelPort、build_model_port 工厂
```

### 3.2 请求体（不含密钥）

```json
{
  "model": "deepseek-flash",
  "messages": [{"role": "user", "content": "<ContextBuilder 输出>"}],
  "stream": false,
  "max_tokens": 1024,
  "response_format": {"type": "json_object"},
  "thinking": {"type": "disabled"}
}
```

禁止出现：`tools`、`tool_choice`、`temperature`、`reasoning_effort`。

> **已由官方文档核对（2026-09-26）**：Chat Completions 文档确认字段为
> `thinking: {"type": "enabled" | "disabled"}`，且**默认 `enabled`**，因此「显式关闭」
> 是必要动作。原先的未验证项 U-M03-1 据此关闭；来源见 `docs/SOURCES.md`（V1）。
> 另据同一文档，异常 `finish_reason`（`content_filter`／`insufficient_system_resource`／
> `aborted`／`tool_calls`）必须显式分类，避免退化成「空 content」。

### 3.3 失败分类

| 分类 | 触发条件 | `sent` |
|---|---|---|
| `EMPTY_CONTENT` | **正常结束**（`finish_reason=stop`）但 content 为空／全空白，或响应没有 choices | True |
| `TRUNCATED` | `finish_reason=length`（优先于内容解析） | True |
| `INVALID_JSON` | content 不是合法 JSON | True |
| `SCHEMA_INVALID` | 非对象、缺 `action`、额外字段、枚举／长度／PASS 约束不满足 | True |
| `REFERENCE_INVALID` | `reply_to_message_id` 不在允许集合；`requested_speaker_id` 是自己或不在允许集合 | True |
| `TIMEOUT` | `httpx.TimeoutException` | True |
| `PROVIDER_ERROR` | HTTP ≥400，或响应不是合法 JSON／不是对象 | True |
| `UNKNOWN_REQUEST` | 网络层异常：请求可能已送达 | **False** |
| `CONTEXT_LIMIT` | prompt 超过 `max_prompt_chars`，**未发送** | **False** |
| `MISSING_CONFIG` | 未配置凭证，**未发送** | **False** |
| `NOT_DISPATCHED` | 其他本地拒绝（如入站参数非法） | **False** |

`sent=False` 的调用**不占用预算**；`UNKNOWN_REQUEST` 必须与 `sent=False` 绑定并保守占用预算。

### 3.4 契约调整（影响 M00 契约）

| 调整 | 理由 |
|---|---|
| 新增 `ModelFailureKind.MISSING_CONFIG`、`NOT_DISPATCHED` | PRD 5.3 明确区分“缺少配置尚未发送”与“发送结果不明”，需要独立分类 |
| 新增 `ReferenceScope`（`actor_id`、`allowed_message_ids`、`allowed_speaker_ids`），并作为 `ModelActionRequest.references` | PRD 4.2 要求服务端校验消息与角色引用；引用范围由 M04 从已提交记录构建 |
| 放宽 `ModelActionResponse` 的 `sent=False` 约束 | 原约束强制 `sent=False` 必须是 `UNKNOWN_REQUEST`，与 PRD 5.3“尚未发送不占用预算”冲突。新规则：`UNKNOWN_REQUEST` ⇔ `sent=False`；`sent=False` 仍不得携带 `draft` |

契约变更已同步更新 M00 契约测试与生成产物（`AGENTS.md` 第 4 节第 5 条）。

### 3.6 需求解释与实现选择

- **I1（系统提示词位置）**：M02 的 ContextBuilder 已把角色、可见材料与规则写进同一段提示词，因此 M03 只发送一条 `user` 消息，不额外拼接 system 内容——避免同一规则出现两份而漂移。角色提示词与开发提示词仍然分离（`AGENTS.md` 第 2 节）。
- **I2（思考开关字段）**：PRD 只要求“显式关闭”，未给出字段名。集中定义、可替换，并登记为未验证项。
- **I3（不自行重试）**：客户端不实现任何重试；网络层异常直接返回 `UNKNOWN_REQUEST` 并留给 M04 决定（M04 也不得自动重发，PRD 5.3）。
- **I4（超时实现）**：使用 `httpx.Timeout(request_timeout_seconds)` 作为总期限；真实联调时可再细分 connect／read。
