### 3.3 行动、引用与模型上下文

- `ActionDraft` 按 PRD 4.2 增加收件人，保持 `extra=forbid`。`SPEAK`／`PASS` 的旧四字段读取可把缺省 `recipient_id` 解释为 null；`PRIVATE` 缺少收件人必须失败。新提示词明确给出五字段完整格式，空字段用 null／空字符串；不通过填造私聊对象来修复非法结果。
- `ActionRecord` 的成功消息允许来自 `SPEAK` 或 `PRIVATE`，`PASS` 仍无消息；只有结构与引用都合法的成功结果推进游标。公共回复、主动私聊、私聊回复与 PASS 的正反组合分开测试。
- `ReferenceScope` 不能只是一个混合消息 ID 集合：至少保留可见公开消息、本人收到的私聊、对应发送者／接收者及快照截止范围。旧 `#序号` 别名只在本次合法集合内解析，解析后仍执行频道与参与者校验；不能从观察者全量索引查回私聊。
- ContextBuilder 输出公共信息和本人私聊的完整可见历史，并标明发送方向和来源类型；推进游标不删除旧消息。提示词包含合法角色 ID、可引用消息 ID 和四种行为规则，模板版本随内容更新，旧请求保存原标识与快照。
- 发给角色的正文、引用预览、会话摘要、数量与最近行动均从后端同一权限结果取得。避免通过隐藏条目占位或全局计数泄漏私聊；角色可见编号采用可见集合内的别名映射，底层持久化及 SSE 仍使用原全局 `seq`。别名必须绑定输入快照，不能按后来刷新后的编号解析旧响应。
- 转述只保存新消息，不解析“某人告诉我”来授予访问权；公开转述或跨私聊转述不得自动拼接原文、原私聊 ID 或回复预览。角色文字是剧情内容，不得覆盖系统规则或获得工具执行权限。

### 3.4 会话存储、版本与升级

1. 消息增加明确的公开／私聊范围及收件人；私聊双方由本场 `agent_id` 关联。会话使用 `scene_id` 加无序角色对唯一确定，A → B 与 B → A 共用一个稳定会话标识。可采用会话表或等价稳定派生索引，但必须满足唯一性、首次成功消息才可见和按最新提交序号排序。
2. 在 004 后新增迁移；不重写 001～004、不删除试用数据。旧消息显式归公开、收件人为空；旧 SPEAK／PASS、公开回复、事件范围与 `schema_version` 保持原含义，不补造私聊会话或行动。
3. 保留所有历史 ID、seq、时间、模板快照、输入证据、游标、优先计数、预算使用量、命令幂等记录及已结束状态。旧场景按自己的已存上限运行，不被当前默认 200 覆盖；可继续的旧场景只在人工控制后使用新协议生成后续行动，不重写原调用。
4. 新增枚举与响应字段属于需要显式说明的契约变化。M00 登记新的 `contract_version` 与提示模板版本，列出旧存储记录的读取默认值、新输出格式和不兼容旧客户端的处理方式；本机前后端配套升级，不默许旧前端把 PRIVATE 当公开消息。事件 `schema_version` 仅在对应事件结构变化时递增，不能为行动变化而把历史事件全部改版。
5. 升级演练使用独立数据库副本，先备份再迁移；分别检查全新数据库、含 001～004 数据的旧库、重复执行迁移及迁移失败回滚。逐项比较消息、行动、预算、游标、快照与幂等记录。回退使用升级前备份和配套旧应用，不宣称旧程序可直接读取新私聊数据。
6. 私聊会话／消息、行动成功状态、游标和优先计数在同一结果事务内提交；注入任一步失败应整体回滚，不留空会话、孤立消息或错误消费游标。已发送请求仍按现有规则保守占用预算，不因落盘失败自动退款或重发。

### 3.5 调度、API、界面与分析接线

- 沿用场景级单个角色请求、全局预算及每角色游标。私聊收件人新增外部信息，发送者自己的消息不自唤醒；非参与者的候选资格只能来自其原有启动机会或可见新信息。
- 最新消息的公开点名／私聊收件人共用连续优先计数，成功普通轮转清零，失败不推进；计数持久化并在重启后恢复。候选多于双方时覆盖第三人等待的反例，不建立每个私聊独立计数来绕过公平限制。
- 新会话列表／查询与角色视角返回沿用现有场景 API 风格，过滤、排序和分页在后端完成；协议在 M00 定义，业务在 M04 实现。观察者可读全场，角色视角只读其合法集合；不存在或无权限的引用不能带回私聊内容。
- SSE 复用已提交事件追赶机制。观察者流可以含全部私聊，但不能作为角色模型输入或角色视角的数据源；角色展示使用后端过滤结果。断线去重、频道切换与刷新都不得创建新调用，不能按每个会话另开运行循环。
- M05 使用生成类型。菜单按后端会话结果展示，首条成功消息后出现，双向消息进入同一会话；视角切换清理前一视角的菜单、计数、回复预览和选择状态，避免缓存残留。控制条始终作用于全场；历史页沿用同一显示规则且只读。
- 角色执行状态与最近成功行动独立渲染；失败保留失败原因，不能变成 PASS。观察者可查看沉默记录，角色视角不展示他人隐藏行动或优先来源；HTML／脚本一律转义。
- M06 在 UI 可选集合和后端材料查找两处拒绝私聊、定向事件和沉默记录。公开转述仅送出新公开原文及其真实作者，不能沿引用补全私聊；被本地拒绝时 `provider_attempts=0`，不得新增供应商请求或挤占角色预算。

按 `AGENTS.md` 5.1 分别留证：

1. **重建检查**：在隔离副本保存需比较的产物后，删除该副本中可再生的 OpenAPI、生成类型和前端构建产物，实际重跑导出、测试及构建；比较连续导出的内容哈希。迁移覆盖新库与旧库，不能只复用已有产物。不要删除工作区 WIP 或真实试用数据库。
2. **反例检查**：检查新增 PC 用例和原失败路径均真实执行、无 skipped／xfail、无删用例／放宽断言；确认 PRIVATE 不能通过公开消息默认值、编号解析、分析选材或缓存绕过过滤。
3. **越界检查**：核对仅触及已登记模块，无多人私聊／摘要／自主开口等扩展；基础测试阻断外网，无真实密钥、认证头、环境变量内容或 `reasoning_content` 入库／入日志；上游仓库不变。
4. **环境矩阵**：分别在变量不存在、空值、占位值环境执行相关配置及未派发路径；隔离自动加载真实 `.env`，仅输出布尔状态／来源／键数量。覆盖分析关闭、可选依赖缺失以及 Mock 可运行；不把缺配置与模型返回失败混为一类。

真实验收使用实现阶段扩展的显式 `--live` 入口及已有配置；先校验每次请求输入输出 token 保守上界，不超过 10,000,000，再记录实际用量与任何超限响应。设定独立库和有限请求预算，未覆盖私聊／回复时记录缺口，不为凑覆盖而无限自动重试。本轮开发授权包含按已有配置执行有限真实验收；真实调用必须与 Mock 分开留档。
