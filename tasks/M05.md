## 一、需求

**R1 页面结构（PRD 7.1）。** 配置页包含场景说明、角色列表、添加／复制入口和运行预算；聊天页以时间线为主体，角色信息侧栏按需展开，底部保留运行控制；行为分析使用**独立抽屉**，不挤占常规阅读空间；历史页可以复用聊天页的只读模式。

**R2 角色卡（PRD 7.1）。** 显示名称与**执行状态**，不显示虚构的心理仪表盘。

**R3 事件与运行状态的视觉区分（PRD 7.1）。** 定向事件展示明确的可见性标记；错误、待生效事件、运行停止原因与普通台词有不同样式；当前待回应对象可高亮，但**不伪造**模型正在思考的具体内容。

**R4 渲染方式（PRD 7.1）。** 发言采用完整消息显示，**不做逐字流式渲染**；生成中按钮仍可接收暂停／结束；模板与模拟模式应清楚标识，**不能把 Mock 场景演示当作 DeepSeek 实际输出**。

**R5 视角一致（PRD 7.2）。** 角色视角必须展示与调用器**实际使用相同**的上下文选择结果，前端不得再实现一套权限。

**R6 文本安全（PRD 7.2）。** 渲染必须转义，不执行模型或事件中的 HTML／脚本。

**R7 观察数据（PRD 7.2、1.2）。** 显示实际调用计数；配置与浏览（切换视图、历史回看）**不调用模型**。

**R8 分析区域（PRD 6.1、9）。** M05 提供**基础界面**：选择本场角色、勾选已提交的**公开**材料、预览将送出的内容；真正的分析调用与结果展示由 M06 接线。不得出现假的“分析完成”状态，也不得让私有背景或定向事件进入候选。

**R9 刷新与断线（PRD 5.4）。** 页面刷新只恢复视图、不重启任务；浏览器断开不自动停止后台场景。

**R10 范围。** 不实现行为分析后端与结果展示（M06）、不新增后端业务能力（除下方登记的只读观察端点）。

## 二、目标

1. 三个视图（配置／聊天／历史）+ 独立分析抽屉，均由**已验收**的后端接口驱动。
2. 运行控制可用，且生成中仍能暂停／结束；时间线按 SSE 实时追加并按 `seq` 去重。
3. 角色侧栏显示执行状态；角色视角直接展示后端返回的上下文。
4. 明确的模拟模式标识与责任边界说明，杜绝“看起来像真实模型输出”的假象。
5. 满足 PRD 第 9 节 M05 通过条件：**组件测试通过**；**操作可用**；**无假完成态**。

## 三、规范

### 3.1 目录

```
frontend/src/
  api/client.ts                  # 唯一 HTTP 出口（类型来自 OpenAPI 生成产物）
  api/contracts.ts               # 契约运行时视图 + 带键名的长度上限类型
  hooks/useSceneStream.ts        # SSE 订阅：按 seq 去重、断线追赶、心跳不入剧情
  components/TimelineList.tsx    # 时间线：区分发言／公开事件／定向事件／待生效
  components/ControlBar.tsx      # 运行控制 + 事件提交
  components/RoleSidebar.tsx     # 角色卡：名称 + 执行状态（无心理评分）
  components/ViewpointPanel.tsx  # 角色视角：直接展示后端上下文
  components/AnalysisDrawer.tsx  # 分析抽屉：选材 + 预览（M06 接线）
  views/ConfigView.tsx           # 配置页
  views/ChatView.tsx             # 聊天页（readOnly 复用为历史页）
  views/HistoryView.tsx          # 历史页 = 聊天页只读模式
  App.tsx                        # 外壳：三个页面入口 + 后端不可用提示 + 责任说明
```

### 3.3 状态与呈现规则

- 运行状态、暂停原因、事件状态、可见范围的枚举全部来自后端契约；前端只做中文标签映射，不自定义状态名。
- 暂停原因必须可见（例如「无新信息（不是会话结束）」），与「人工暂停」「接口错误」「上下文超限」「进程中断」区分。
- `model_configured === false` 时聊天页显示**模拟模式**标记，明确「当前为确定性 Mock，不代表真实模型输出」。
- 分析抽屉在未接线时给出明确说明，且**不渲染**「开始分析」按钮。

### 3.4 跨模块扩展（已登记）

为满足 PRD 7.1「角色卡显示名称和执行状态」，M05 需要角色级运行状态，而 M04 只提供了场景级状态。因此新增**只读观察端点**：

```
GET /api/scenes/{scene_id}/agents/status → AgentStatusListView
```

- 位置：`role_theater/api/runtime.py`（M04 的观察面），契约模型 `AgentStatusView`／`AgentStatusListView` 已登记 registry；
- 只暴露运行事实（是否行动过、上次行动结果、已处理到哪条、是否被点名、发言条数），**不含**任何心理或关系评分；
- 不改变 M04 的既有行为与断言，属于**追加**；已同步更新 M04 报告与 `docs/ARCHITECTURE.md`。

### 3.6 需求解释与实现选择

- **I1（前端不引路由库）**：三个页面用顶层状态切换。理由：首版只有三个视图，引入路由库只为状态切换。
- **I2（SSE 与轮询并存）**：时间线初始用 `GET /timeline`，之后由 SSE 追加；SSE 有新条目时顺带刷新状态与角色卡。页面刷新只重建视图，不影响后台场景。
- **I3（生成中的显示）**：只显示「有一次调用进行中」，不显示任何“正在思考的内容”（PRD 7.1）。
- **I4（历史页）**：复用 `ChatView` 的 `readOnly` 模式，不复制一套只读组件。
- **I5（模板编辑）**：复用同一表单，点击「编辑」把模板载入表单并把主按钮变为「保存修改」。
- **I6（角色执行状态的语义）**：仅表示“是否行动过／上次结果／已处理位置／是否被点名”，不做任何推断。
