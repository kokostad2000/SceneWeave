## 6.2 接入 DeepSeek 真实 API 的准备（2026-09-26）

按官方文档核对接口契约后（`docs/SOURCES.md` §1.1），本次修复了三个**真实缺陷**并补齐了联调路径：

| 缺陷／缺口 | 性质 | 处置 |
|---|---|---|
| `Settings` 设了 `env_file=None`，**`.env` 被静默忽略**；而文档与预期都以为 `.env` 生效 | **配置缺陷**：用户按常规做法放 `.env` 会毫无效果 | 支持 `.env`（仓库根与 `backend/`，绝对路径，不受工作目录影响）；新增 `.env.example` 模板并在 `.gitignore` 中显式保留；健康检查新增 `model_credential_source`（`environment`／`dotenv`／`none`，**不含内容**），便于确认 `.env` 是否真的被读取 |
| `SCENEWEAVE_MODEL_NAME` 只被读入配置、**未注入运行器**（`ModelActionRequest` 恒用 `ModelParams()` 默认值） | **配置未生效** | `SceneRunner` 接收 `model_params`，由 `main.py` 用 `settings.model_name` 注入；测试断言落盘的 `requested_model` 与配置一致 |
| 解析器只处理 `finish_reason=length`，其余异常取值（`content_filter`／`insufficient_system_resource`／`aborted`／`tool_calls`）会退化成「空 content」 | **失败分类缺陷** | 按官方文档全部显式分类，并在解析内容**之前**判定 |

同时：

- 新增 `backend/scripts/live_integration.py`：用**真实端口**驱动完整应用栈（建场景 → 真实三人聊天 → 定向事件 → 视角可见性核对 → 只读分析），证据写入 `state/reports/live/`（不含密钥）；与 `live_smoke.py` 一样需要 `--live` + `--confirm-spend` + 密钥三重条件，缺任一即拒绝运行（退出码 2／2／3，已实测）；
- **测试隔离**：所有测试以 `_env_file=None` 构造 `Settings`，因此操作者的真实 `.env` **永远不会**被测试读取（避免跑测试就花钱）；并有专门用例在「仓库存在 `.env`」的情形下仍全绿（实测 **375 passed**）。
- 网络自检：本环境到 `api.deepseek.com:443` 的 TCP 连接成功，请求体与官方契约一致。

**仍未验证**：真实调用本身（缺 `SCENEWEAVE_MODEL_API_KEY`）。填入 `.env` 后执行
`uv run python scripts/live_integration.py --live --confirm-spend` 即可补齐 §4 的真实验收项。

**`.env` 落地（2026-09-26）**：已按 `.env.example` 在仓库根创建 `.env`（密钥留空，权限 600）。
验证结果：`Settings()` 能读到该文件（`env_files_present=['.env']`）、空密钥时 `model_configured=false`
且**回落确定性 Mock**（不联网）、健康检查仍 200 并报告 `model_credential_source="none"`；
`.env` 存在时全量测试仍 **375 passed**（测试不读取它）。

**实测的路径优先级（新增结论）**：两个 `.env` 同时存在时 **`backend/.env` 覆盖仓库根 `.env`**
（后加载者优先），因此建议只保留一处；该结论已写入 `docs/RELEASE.md` §6.1 与 `.env.example` 注释，
避免操作者因两处配置不一致而困惑。
